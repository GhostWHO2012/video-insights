Hamel Husain 介绍一组用于 AI 产品评测的 Claude Code Skills。它们覆盖错误发现、数据审阅、评测审计、合成数据、评审提示词、评审器验证和 RAG 等环节。视频反复强调，Skill 是帮助团队形成正确工作顺序的工具，不会替人决定什么算好的产品行为。

## 00:00 为什么写评测前要先看失败案例

如今上线 AI 产品比以前容易，但判断系统在真实使用中是否按预期工作仍很难。Hamel 最常见到的错误，是团队还没读过调用轨迹，就开始写一长串 eval。

只有先看失败案例，团队才知道哪些问题真实出现、如何描述它们，以及该把验证资源投到哪里。

## 00:32 在哪里找到评测 Skill

这组 Skill 放在公开的 GitHub 仓库中，README 说明了各项用途和使用时机。入口 Skill 是 `evals-start`，负责根据用户所处阶段引导到合适的流程。

开发者可以在 Claude Code 等编程智能体环境中使用它们。选对入口比一次加载全部材料更重要。

## 00:49 八个 Skill 概览

核心是 `error-discovery`：已有轨迹、却不知道失败模式时先用它。已有 eval 则可用 `eval-audit` 查缺口。其他 Skill 分别帮助生成合成数据、写与验证 LLM 评审、搭建审阅界面及评测检索。

这些工具对应评测生命周期的不同问题。Hamel 明确建议先从错误发现入手，再考虑自动化评分。

## 01:57 错误发现：让 agent 理解数据

`error-discovery` 会先检查数据结构，弄清一条 trace 包含哪些字段、有哪些类型的对话和工具调用，然后协助寻找值得人工审阅的样本。

它的目标不是直接宣告“这些就是全部错误”，而是帮助人系统地浏览数据，并逐渐形成可靠的失败分类。

## 02:31 设计标注界面

真实轨迹可能很长，直接读 JSON 或日志很费力。`build-review-interface` 帮团队制作适合当前数据的审阅界面，把对话、工具调用和标签放在一个地方。

好的界面让专家更容易判断发生了什么，也降低持续标注的成本。界面设计因此是评测质量的一部分，而不只是美化数据。

## 03:14 真实案例：租房助手的标注界面

视频展示了一个为租房助手定制的标注界面。审阅者可以看到来电者和助手的往返对话、系统提示及工具调用，而不是只看最后一句回答。

这个例子说明标注工具应随数据与任务而设计。对语音租房助手重要的字段，未必适合直接照搬到邮件或 RAG 应用。

## 04:48 按多样性抽样，而非只看高频样本

如果只随机抽取或只看高频场景，很可能反复读到同类简单请求，却漏掉少见但严重的失败。Hamel 建议按主题或行为聚类，再从各簇抽样。

抽样的目标是探索整个使用空间，尽快发现不同种类的问题，而不只是估计某个已知问题有多常见。

## 05:41 审阅循环：广度与深度

审阅先追求广度，找出可能存在的失败类型；发现某一类问题后，再深入看更多类似样本，弄清边界与频率。两种模式需要交替进行。

Skill 可以跟踪标注进度，提醒何时还在发现新问题、何时同类样本已接近饱和。最终的类别仍要由熟悉产品的人确认。

## 07:06 评测审计 Skill

已有 eval 不等于评测体系可靠。`eval-audit` 会检查指标是否基于观察到的失败、样本是否充分，以及 LLM 评审器有没有经过人工标签验证。

它还能提示数据泄漏、评审过程不规范或某类失败覆盖不足等问题。审计结果是一份供团队核对和修正的报告，不是自动颁发的合格证书。

## 08:06 二元通过／失败优于 1–5 分和字母等级

对于一项具体失败，Hamel 倾向用“通过／失败”给出清楚判断。1–5 分或字母等级看起来更细，却要求团队反复协商每一档的含义。

把每个 eval 限定在一种可描述的行为，才能写清上线门槛，也让误判更容易被发现和修正。

## 08:41 用人工标签检验 LLM 评审

`validate-evaluator` 检查 LLM 评审是否与人工判断一致，也留意评审器是否“偷看”标签或在测试数据上作弊。只有经过独立样本验证，自动评分才值得信任。

它还会检查不同失败模式是否有足够的标注数据。数据不足时，报告应指出缺口，而不是用一个看似精确的通过率掩盖不确定性。

## 09:48 最值得优先投入的两项 Skill

Hamel 最推荐优先投入 `error-discovery` 和 `eval-audit`：前者帮团队从真实数据中发现该评什么，后者检查已有评测是否抓住重要失败并正确运作。

这两项分别解决“从哪里开始”和“现在做得是否可靠”。即使暂时不用其他 Skill，做好这两步也能显著改善评测工作。

## 10:06 合成数据、评审提示词、RAG 等其他 Skill

产品尚未上线、缺少真实用户时，合成数据 Skill 可帮助构造多样情境，测试系统边界。另有 Skill 帮写评审提示词、用人工标签验证评审器，以及为 RAG 的搜索和检索建立评测。

这些工具应服务于已明确的问题：合成输入不能替代真实数据，漂亮的评审提示词也不能替代对产品成败标准的判断。

## 写在最后

这八个 Skill 的共同价值，是把评测工作安排成可复查的循环：读数据、发现失败、请领域专家标注、建立清楚的 eval，再审计自动判断是否可信。Claude Code 能加快各环节，但真实数据和人的判断仍是起点。
