# Mike Krieger：AI 时代的构建方式，是把雄心、委派和取舍都重新训练一遍

> “你要大胆提出高要求。”

> “评审瓶颈不是时间，而是理解。”

> “你必须愿意把第一代 AI 产品原语下线掉。”

Mike Krieger 的特殊之处在于，他不是只从产品管理角度谈 Anthropic，也不是只从工程角度谈 Claude。他曾是 Instagram 联合创始人，也在 Anthropic 做过首席产品官，后来又主动转成 Labs 的个人贡献者。这个身份变化让他对 AI 构建方式的判断更具体：模型不只是提高开发效率，而是在改变一个人如何提出需求、如何委派任务、如何评审代码、如何组织团队，以及如何决定继续推进还是关掉。

这场对话最核心的线索，是“不要把模型当成小工具”。当模型越来越能写代码、运行脚本、访问环境、处理多步骤任务时，真正稀缺的不是会不会用 prompt，而是人有没有足够大的问题意识、足够清楚的判断标准，以及足够快的组织学习能力。

## (00:00) 从首席产品官转为 Labs 的个人贡献者

Mike 说，自己在 Anthropic 的前两年是首席产品官，但看到内部越来越多人用模型做开发后，FOMO 越来越强。产品策略当然也可以用 Claude 来批判文档、帮忙梳理思路，但那和亲自用模型构建产品仍然不同。于是他开始把周末大量投入到实际开发里，最后意识到自己需要做一次角色转变。

这个转变很有代表性：AI 让一些原本在组织里偏管理、偏产品、偏战略的人重新回到一线。不是因为管理不重要，而是因为构建本身的门槛、速度和反馈方式变了。过去一个想法需要拆成工程任务、排期、评审和协调；现在一个有经验的人可以直接和模型一起把原型推到可运行状态。

他提到 Anthropic 内部拿到后来成为 Mythos 和 Fable 的模型快照时，构建范式开始明显变化。以前他会按传统工程方式把问题在脑中拆解、逐步迭代；现在更多是和模型协作，把更大的目标直接交给它，再围绕结果不断验证和修正。

## (02:55) 要大胆提出高要求，以及为什么人们仍然只敢问小问题

Mike 很喜欢“大胆提出高要求”这个说法。他举了一个内部产品问题的例子：有人觉得某个工具没按预期工作，想让他做修改，他的反应是，为什么不直接问 Claude？而且对方并不是技术背景。这说明现在的问题不只是模型能力，而是人还没有习惯把大一点的任务交给模型。

他进一步指出，第一代 AI 产品把模型限制得太死：工具权限有限、环境访问有限、运行能力有限，所以用户很难提出真正大的请求。你想让它修复问题，它可能只能写代码，不能运行；你想让它处理 PDF，它可能被内置解析器卡住，却没有权限自己写脚本解决。

这段的洞见是，AI 产品设计不该只考虑“安全地回答问题”，还要考虑如何让用户形成更大的任务想象力。很多人问小问题，不是因为他们没有大需求，而是产品没有让他们相信大请求真的可行。

## (04:51) 一个周末把 Python 迁移到 TypeScript

Mike 提到自己做过一个很大胆的周末项目：把整个 Python 代码库迁移到 TypeScript，让它能运行、能部署。这件事在过去可能需要团队规划、长期迁移和大量人工检查，但现在可以通过动态工作流、反复验证和模型协作，在极短时间里推进。

他把这个经验和 Instagram 当年 Python 3 迁移、类型提示、MonkeyType 联系起来。Instagram 当时通过捕获生产环境中的运行时类型，再映射回代码库，帮助团队在大型 Python 系统里逐步引入类型。这说明大规模迁移从来不是只靠决心，而是靠可验证的反馈系统。

AI 让迁移速度变快，但它并没有取消工程判断。你仍然需要知道什么要验证、哪些行为不能破坏、哪些类型和接口代表真实生产使用。模型能放大执行力，但前提是人能给出足够清楚的验证框架。

## (06:48) 来自 2010 年的规模化经验：衡量一切，构建可调开关

Mike 回忆 Instagram 上线后第一个星期后端几乎崩溃，他们从一次基础设施午餐里得到两条长期受用的建议：提前测量所有东西，以及认真对待配置项和功能开关。最糟糕的情况，是故障发生时你才发现自己没有基线，不知道当前数字到底是否异常。

这两条经验在 AI 时代仍然成立，甚至更重要。模型产品里充满动态权衡：不同模型、不同功能、不同用户、不同运行时策略，都需要快速调整。如果没有监控、指标和运行时配置能力，团队会在变化速度面前失去控制感。

这也是为什么 AI 产品不能只靠“发布一个版本”。更准确地说，你发布的是一个持续变化、带大量开关、需要实时校准的系统。可观测性和可调节性，变成产品构建的一等公民。

## (08:06) 在 Slack 里 @ Claude，以及多人协作式任务委派

Mike 说 Anthropic 内部很多 Claude 使用并不完全像 Claude Code 那种高频交互，而更像通过 tag 把任务委派出去。你可以在 Slack 里 @ Claude，不只是让它修 bug，而是让它负责代码库的一部分、监控反馈渠道、主动承担任务，甚至在 API 变化时继续处理相关修改。

这个模式很像多人协作。它让大家看到别人如何使用 Claude，也会扩展团队对模型能力的想象力。就像 Midjourney 在 Discord 上让人通过旁观学会更大胆地提示，Anthropic 内部的 @ Claude 也让人看到“原来可以这样委派”。

这段最重要的是，AI agent 不只是个人效率工具，也会成为组织协作界面。一个任务不再只能分派给人，也可以分派给模型；而其他人能看到这个过程、学习它、复用它。

## (10:37) 评审瓶颈不是时间，而是理解

当 Claude 生成大量代码后，评审方式也必须变化。Mike 提到，别人给你一个 2000 行 PR，你看起来只会觉得“这就是代码”。真正需要分享的不是更多代码，而是这次改动的意图、权衡、Claude Code artifact，以及为什么这么改。

他现在不会假装自己审过每一行代码，而是会和 Claude 讨论：这些是我有疑问的地方，你去查一下。这是一种由 Claude 驱动、但仍由人主导的代码审查。代码本身可以通过测试和生产指标验证，但人更需要理解意图和风险。

这说明 AI 时代的评审瓶颈不只是“没有时间看完”，而是“看完也不一定理解”。未来更重要的协作材料，可能是解释、权衡、验证结果和生产指标，而不是单纯的 diff。

## (11:53) 继续推进还是转向，以及不管人的项目负责人

Anthropic Labs 的组织方式围绕快速实验展开。Mike 说他们每两周有一次评审，每个项目都要回答：继续推进还是转向，甚至直接关掉。每个周期都会关掉一些项目，所以团队逐渐不会把项目关停等同于个人失败。

这种机制的关键，是组织结构不能和单个项目绑得太死。否则每两周项目变化一次，组织就得重组一次，会非常痛苦。Labs 采用更灵活的 bets 或 pod 方式，从产品、工程等不同团队临时拉人，先快速原型，内部上线，再根据结果决定是否固化团队。

这里的洞见是，AI 加速了实验，也会迫使组织结构变轻。项目负责人不能只是“管人”，而要能围绕一个 bet 拉起资源、推进判断、接受评审，并在必要时体面地关掉项目。

## (13:43) Claude Design 接下来会走向哪里

Claude Design 一开始也是临时小组，后来随着发布、获得关注、迭代扩大，逐渐变成更正式的团队。Mike 认为它下一步的关键，是更好地和 Anthropic 其他产品界面互动，让设计、代码、应用之间的边界更模糊。

他提到自己在设计东西、和 Claude Code 对话时，希望体验更无缝：一边讨论设计，一边做交互，一边让不同服务互相协作。现在各个服务之间互操作不够好，压制了许多有趣想法。

Claude Design 的方向不是单独做一个设计工具，而是让 Claude 更少受限制，让 app、design、code 之间的界限逐渐融合。用户可能会构建完整可用的应用、游戏或交互原型，而这并不一定是产品最初被设计出来的用途。

## (15:37) Project Unship，以及他想删掉什么

当被问到想在 AI 产品里删掉什么，Mike 提到 Anthropic 有一个 Slack 频道叫 Project Unship，专门讨论哪些产品功能应该被下线。这件事在 Instagram 时期也很难，因为很多功能使用率只有 4% 到 5%，但每个小功能都有自己的用户群，最后容易变成 Microsoft Word 式复杂性。

他举例说，Claude 最近下线了 Styles，因为它使用率小，而且并不真正符合 AGI 的产品思路。Styles 的方式太规定性，而 Skills 是更好的承载方式。这说明 AI 产品的原语也会迭代，第一代看起来合理的功能，可能需要被下一代能力替换。

他更大的担忧，是用户被迫区分 code、co-work、chat 等不同服务，而这些服务之间又不能很好互操作、互相委托。普通用户很难解释它们为什么不同。这说明 AI 产品现在最大的复杂性，可能不是功能少，而是边界太多。

## (17:34) 当大模型公司迭代这么快，为什么还要创业

现场有人担心，大模型公司明天可能发布一个功能，就摧毁一个创业方向。Mike 的回答不是否认这种风险，而是把它放回创业史里看。Instagram 当年也会被问，如果 Google 推出照片产品怎么办。但大公司往往会做出符合自己体系和优势的产品，而不是像创业公司那样深扎一个人群或场景。

他认为，模型会解锁下一代初创公司，不是因为模型替代了创意或品味，而是因为它让实验成本大幅下降，让行动速度变快。创业公司的机会在于激光一样专注某个垂直领域、某个行业或某群用户，达到大模型实验室很难达到的理解深度和用户喜爱。

这段的关键是：AI 会让很多功能被平台吸收，但也会让更多细分场景值得被做。创业者不能只做一个薄薄的功能层，而要抓住大公司不可能深入理解的具体工作流和人群。

## (20:06) 垂直 AI 与金融

谈到金融场景时，Mike 认为这是一个能明显看到模型一代代变强的领域。一些金融 AI 初创公司已经建立自己的 evals，用来追踪金融用例是否真的变好。虽然 Anthropic 不会刻意迎合这些 evals，但它们可以成为观察能力进步的晴雨表。

金融场景的难点，在于它既需要模型的灵活性，又需要数据可验证、审计日志和来源追踪。如果一切完全自由发挥，就会变得混乱，这不是金融服务公司想要的；但如果系统为了可审计性变得过度僵硬，又无法承载 agentic 的上层工作负载。

垂直 AI 的诀窍，就在于找到这条边界：既保留经过验证的数据和可追踪流程，又允许模型在其上即时生成分析、仪表板和工作流。真正的机会不是让 AI 随便回答金融问题，而是让它在可信数据和灵活操作之间建立新接口。

## (22:00) 倦怠、996，以及如何保持清醒

Mike 承认今天 AI 行业强度极高，变化速度远超过过去。Instagram 时代可能一年担心一次 WWDC，几个月才有竞争对手发布新东西；现在 Anthropic 的每周全员会上都会有一页“AI 本周”，而且标题后面还要加一句“才周三”。

面对这种速度，他强调真正留出休息时间。联合创始人也会提醒团队，倦怠一旦发生，恢复会非常久，没有哪份工作重要到不能离线几天。这不是软性福利，而是保持长期判断力的必要条件。

他也提到要给自己足够的工作外身份。比如他有孩子之后，会在睡前固定陪伴，这反而成为一种强制切换。AI 行业会不断制造“你错过了什么”的焦虑，但如果人持续透支，最终会失去继续构建的能力。

## (25:04) 作为领导者，把情绪说出来

最后 Mike 讲到领导者要能把情绪说出来。比如项目被关掉时，他会在会议一开始承认自己很难过、很沮丧、希望它能做成。这不是削弱领导力，而是给其他人也表达真实感受的空间。

当团队能承认失望、生气和难过，才更容易进入下一步：我们接下来怎么办。否则情绪会在组织里变成隐性阻力，让项目关停、转向和复盘都变得更困难。

这和 Labs 的快速实验文化是连在一起的。你不能一边要求团队每两周关掉项目，一边假装每次关停都毫无感觉。真正成熟的高速组织，需要同时允许高强度执行和真实情绪表达。

## 写在最后

这期对话最值得带走的判断是：AI 时代的构建能力，不只是“让模型写更多代码”。它要求人学会提出更大的请求，学会把任务委派给 agent，学会用指标和开关控制动态系统，学会从代码评审转向意图评审，也学会更快地关掉不再成立的产品原语。

Mike Krieger 的经验把 Anthropic Labs 的工作方式讲得很清楚：模型让实验更快，但不会替代人的雄心、品味、组织判断和情绪管理。真正能穿过这轮变化的人，不只是会用 Claude 的人，而是能重新训练自己如何构建、如何评审、如何取舍的人。
